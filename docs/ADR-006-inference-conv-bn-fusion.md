# ADR-006: Explicit inference-only Conv/BatchNorm folding

Accepted for the authorized v7 deployment repair, 2026-10-26. The unfused v7 pair+TTA exceeded the unchanged 100 ms local limit; the bounded diagnosis reproduced ~106 ms under both cuDNN settings, with ~34 ms in EfficientNet forward+TTA. The original failure is a real resource failure, not a defective accuracy result. The original probe's smaller margin was insufficient.

Add optional boolean `fuse_conv_bn` to each inference bundle member, default false. Initially allow it only for efficientnet_v2_s. After loading its original trusted checkpoint, eval-only consecutive Conv2d/BatchNorm2d pairs in Sequential containers are folded using PyTorch's existing fusion utility. Work on a deep copy; never rewrite trained weights, training config or optimizer state. No training behavior or dependencies change. ConvNeXt remains unchanged. The same Predictor is used for validation, prediction and cost. The exact bundle bytes bind this optimization to the prediction manifest and runtime checks.

Predeclared acceptance: generic nontrivial BN and actual EfficientNet FP32 equivalence at rtol=2e-4, atol=2e-5; reject training/stateless BN and invalid flags; preserve original state and legacy defaults. One fixed label-free 100+5, three-round batch1 resource trial of the fused pair; record all rounds and maximum FP16 probability difference against its unfused predictions, requiring max absolute difference <=0.002 and unchanged repeated predictions within 1e-7. Fusion changes floating-point rounding, so do not claim byte-identical predictions. No new shapes, TTA variants, fusion ratios, epochs, image sizes or labels enter this resource decision.

Only if those checks pass, archive the unfused v7 configuration, failure status/log/timing and their SHA hashes before replacing the v7 candidate with the explicit fused variant. This is a documented deployment deviation after the internal recipe was frozen; architecture, epoch6, seed, training data, TTA and equal weights remain fixed. Then run a fresh full official-valid comparison against fixed v6, the original strict promotion gate, final packaged timing/size/CRC/hash/binding checks and visual declaration review. Validation reuse remains exploratory. No new test prediction until the frozen fused candidate passes validation. Never relax 100 ms or claim official T4 verification.

Rollback: use the archived unfused bundle with default false, or the preserved v6 delivery. Original checkpoints and all previous participant files remain intact.

Outcome: the first fixed fusion trial measured 103.34104066666696 ms and therefore **failed** the resource gate. Maximum FP16 probability delta .0002997368574142456, repeated delta0; 44 verification tests passed. The fused probe was not promoted, the original candidate was not replaced, and no v7 test prediction was generated. Any fallback is a separate documented experiment (OPTIMIZATION-v7b.md).
